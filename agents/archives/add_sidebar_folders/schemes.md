## 目标

侧栏从「全库平铺文件」改为「当前目录浏览」：可多层文件夹、在当前目录新建文件或文件夹，文件夹可置顶 / 重命名显示名 / 删除。搜索与「选择文档」链接仍覆盖全库。已有根目录笔记迁入 `documents/`，图片仍与对应 `.md` 同级。

## 方案

笔记树根改为 `MindRecall/documents/`。用户文件夹磁盘名为时间戳 id；显示名写在目录内 `{id}.fileconf`（无 conf 则显示磁盘名；重命名只改 conf）。`+` 改为下拉「新建文件 / 新建文件夹」；新建文件 UX 与现在相同但落在当前目录。侧栏只渲染当前层；列表上方「返回上级」在根目录隐藏。点击文件夹只改当前目录，不开关已打开文档；当前篇不在本层则不高亮。

排序（当前层）：置顶文件夹 → 置顶文件 → 未置顶文件夹（建立时间）→ 未置顶文件（修改时间）；两类置顶各自按后置顶靠前。`{id}_assets`、`trash`、`*.fileconf` 不出现在侧栏与搜索。全库笔记维持内存索引，供搜索与插入链接；点搜索结果打开文档时，当前目录跟到该文件父目录（与冷启动一致）。冷启动恢复上次打开的文档，侧栏跟到其父目录并回写 session。

删除文件夹（无论空否）整棵进入 `MindRecall/trash/{folderId}/`；单文件仍平放到 trash 根（有内容才进站，空文档直接删，与现在一致）。`trash/manifest.json` 记录 id 与相对 `documents/` 的原父路径；恢复时父目录还在则回原处，否则放到 `documents/` 根。备份仍跳过整个 `trash/`。

## 已决事项

- 笔记根目录为 `MindRecall/documents/`，与 `trash/` 等兄弟目录分离
- 允许多层嵌套；新建文件建在当前目录，UX 与原新建文件相同
- 文件夹磁盘名 = 生成时间戳 id（与笔记 id 同策略，全树唯一）；显示名在 `{id}.fileconf`；无 conf 则用磁盘名；创建时 conf 显示名与磁盘名一致
- 重命名文件夹只改 conf，不改、不移动目录；显示名允许特殊字符；空显示名不算创建/重命名成功
- 搜索、插入文档链接 = 全库（内存索引，禁止每次为搜索扫盘）；侧栏普通列表 = 当前目录
- 冷启动：打开上次文档，侧栏跟到该文件父目录；从搜索结果打开文档时同样跟到父目录
- 当前目录写入 `session_cache.json`；冷启动以「上次打开文件的父目录」为准并回写；仅当该文件找不到时才用已持久化的当前目录
- 浏览子目录不等于操作文档：不切换已打开篇，不在当前层则不高亮
- 根目录隐藏「返回上级」（不置灰）；搜索结果列表期间也不显示该按钮
- 文件夹菜单与文件菜单同款：置顶/取消置顶、重命名、删除（不要「在资源管理器中显示」）
- 图片目录与对应 `.md` 同级；不放宽 `../` 解析
- 删除文件夹整棵进 trash，恢复整棵；原路径记在 `trash/manifest.json`；父目录不存在则恢复到 `documents/` 根
- 首次升级把 `MindRecall/` 根上已有 `.md` / `.txt` 及对应 `{id}_assets` 迁入 `documents/`（跳过 `trash/`）
- 列表仍用现有侧栏行（文件夹换新 icon），不新开一栏

## 关注点

- `MemoStorageService.memosDirectory()` / `_fileForId` / `createMemo`、`MemoImageService.assetsDirectory`、`MemoTrashService.restore` 均假定文件在 `MindRecall/` 根；必须改到 `documents/` 或按 id 在树内查找，禁止只改 UI
- `MemoWorkspaceController.memos` 当前同时服务侧栏、搜索、链接、启动恢复；必须拆成「全库索引」与「当前目录条目」，`runSearch` / `LinkInsertDialog` 只吃全库
- `performSave` 今日就地改 `memos`；保存后须同步全库索引与当前层，且不得把别的目录的文件插进当前列表
- `_resolvePath` 继续拒绝目录外路径；插入图片仍用 `./{id}_assets/…`
- 侧栏列举必须排除 `trash`、`*_assets`、`*.fileconf`；id 在文件与文件夹之间全局唯一（冲突则换新时间戳）
- `.fileconf` 只存显示名，禁止写入回收站原路径；备份会拷到 `documents/` 树内，搜索必须排除
- 删除的文件夹若包含当前打开篇：按删除当前篇处理（切到树外剩余篇或新建）
- 空文件夹也进 trash（与空文档直接删不同）
- 同 id 再次进 trash：覆盖 trash 内旧项并覆盖 manifest 对应条
- 不把实现细节写进 README 以外的用户可见文案；README 须同步目录树与侧栏/存储行为
