## 目标

侧栏当前目录列表可为文件和文件夹「移动到」已有目录（含 `documents/` 根）。选目录交互类似浏览器移动书签：树里点选，再确认。搬完侧栏不跟、不切正在编辑的文档。搜索结果不做移动。

## 方案

当前目录列表的长按与行尾 `⋮` 共用菜单，增加「移动到」。弹出对话框：只显示「根目录」与文件夹树（笔记不出现）；行点击选中，箭头展开/折叠；根目录默认展开，子文件夹默认折叠。当前所在父目录可显示为选中，但确认禁用。移动文件夹时从树中去掉自己及全部子孙。确认后把文件（`{id}.md` + 同级 `{id}_assets/`）或整棵文件夹目录 `rename` 到目标相对路径；id 不变。工作区只刷新全库索引、`filePath` 与当前层列表，不改 `currentRelativeDir`、`activeMemoId`、标题/正文 controller。成功/失败用现有 `_showMessage` Snackbar。弹窗内不能新建文件夹。

## 已决事项

- 长按与 `⋮` 视为同一菜单，两处都出现「移动到」
- 选目录只列文件夹 +「根目录」，不列笔记
- 当前所在父目录显示可选中，确认按钮禁用
- 搬完侧栏留在原地（不进入目标目录）
- 不切文档、不重置编辑器；只更新路径，用户感觉文档没变
- 文件夹树可展开/折叠；根目录默认展开，其下默认折叠
- 搜索结果不加菜单、不做移动（后续迭代）
- 弹窗内不能新建文件夹，只选已有目录
- 文件夹也能移动；树中直接剔除自己和子孙（禁止移入自身子树）
- 成功/失败用 Snackbar（文案对齐「已重命名 / 重命名失败」）
- 行点击只选中；展开/折叠只走行首箭头，互不抢手势
- 每一层文件夹排序与侧栏未置顶/置顶规则一致（置顶文件夹靠前，其余 `createdAt` 新→旧）

## 关注点

- 图片仍与 md 同级；禁止放宽 `_resolvePath` 的 `../`；搬文件必须连 `{id}_assets/`，搬文件夹用整目录 `rename`（内部相对图片路径不用改正文）
- `Memo.copyWith` 目前不带 `filePath`；移动后必须用新路径更新全库 `memos`（可 `listMemos`），禁止只改磁盘却留着旧 `filePath`（插图和「在资源管理器中显示」会坏）
- 禁止调用 `applyMemoToEditors` / `openMemo` 来「同步路径」，否则会重写 controller、光标和历史，用户会觉得换了篇
- 先 `flushSave` 再搬，避免写回旧路径
- 目标必须落在 `documents/` 内，走已有 `MemoFs.resolveRelativeDir`；非法或越界路径失败并 Snackbar
- 存储层若目标已有同 id 则失败（正常不会撞；不要静默覆盖，以免毁掉无关条目）
- `dirEntries` 只刷新当前层，禁止把其它目录文件插进当前列表
- 置顶按 id，搬家后不必改 pin 列表
- 搜索 UI（`_buildSearchResults`）本迭代零改动
- README 同步用户可见行为与新 dialog 路径
